## [v26.1.9](https://github.com/redpanda-data/redpanda-operator/releases/tag/charts%2Fredpanda%2Fv26.1.9) - 2026-07-14
### Fixed
* `helm upgrade` no longer fails under Helm 4's default server-side apply when SASL is enabled. To keep the generated bootstrap-user password stable, the chart looks up the existing `*-bootstrap-user` Secret on upgrade and re-renders it — previously verbatim, including the server-set `metadata.managedFields`, which the API server rejects with `metadata.managedFields must be nil` when Helm 4 applies manifests server-side. The rejected apply also polluted release history: manifests stored by any successful client-side upgrade carried `managedFields`, so later server-side rollbacks failed the same way. The lookup now strips `managedFields`, `resourceVersion`, and `uid` before the Secret is re-rendered.
