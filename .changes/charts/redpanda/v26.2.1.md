## [v26.2.1](https://github.com/redpanda-data/redpanda-operator/releases/tag/charts%2Fredpanda%2Fv26.2.1) - 2026-07-28
### Added
* Added Gateway API TLSRoute support for external access (**Beta**). Individual
external listeners can opt into TLSRoute mode via `type: tlsroute` (a
per-listener type that overrides the cluster-wide `external.type`), enabling
SNI-based routing through a user-managed Gateway. Supports per-listener
domains and gradual migration from NodePort/LoadBalancer to Gateway API.

Beta status: the API surface (chart values under
`listeners.<proto>.external.<name>.type` and `external.gateway`) may
still change in backwards-incompatible ways before GA. Production use is
not recommended; please file issues with feedback on the values shape and
rendered TLSRoute objects.
* `tuning.apply_host_tuners` (default `false`) gates a chroot-based tuning
init container that gives `rpk redpanda tune all` real access to the
host's `/sys`, `/proc`, NICs and block devices. When enabled, tuners
that previously failed inside the pod sandbox — `disk_irq`,
`disk_scheduler`, `disk_nomerges`, `net`, `fstrim`, and (on GCP)
`disk_write_cache` — are default-enabled and actually apply, along
with `cpu` (a no-op on VMs without cpufreq). An
explicit `config.rpk.tune_*: false` overrides any of these defaults.
The broker reads the net tuner's cpuset state file, so dedicated-IRQ
(sq/sq_split) modes keep reactor shards off IRQ-pinned CPUs.

Opt-in only; the default tuning container is unchanged, and
`tune_aio_events` must remain enabled. Requirements and caveats:

- Broader security posture than `tune_aio_events` alone: in addition
  to the privileged init container, the pod mounts twelve hostPath
  volumes (`/bin`, `/sbin`, `/usr`, `/lib`, `/lib64` read-only;
  `/sys`, `/proc`, `/etc`, `/dev`, `/var`, `/run` writable; plus the
  tuner state file). PSA `privileged` namespaces, or an OpenShift SCC
  permitting hostPath and privileged containers, are required.
- Run at most one Redpanda pod per node (the chart's default
  anti-affinity): concurrent tuners race on kernel parameters.
- Rollback is not automatic: disabling the flag or uninstalling stops
  future runs but already-applied sysctl/IRQ/block-device tuning
  persists until node reboot, and the fstrim systemd timer rpk
  installs on the host keeps firing until removed.
* Added `statefulset.persistentVolumeClaimRetentionPolicy` to expose the StatefulSet's `PersistentVolumeClaimRetentionPolicy`. Defaults to `whenDeleted: Retain` / `whenScaled: Retain` (matching the Kubernetes default). Set `whenScaled: Delete` to delete a broker's PVC when it is removed via scale-down, and `whenDeleted: Delete` to delete all PVCs when the StatefulSet is deleted.
### Changed
* The PVCUnbinder sidecar's ClusterRole (rendered when both `rbac.enabled` and `statefulset.sideCars.pvcUnbinder.enabled` are set; with `rbac.enabled: false` the new verbs must be added to your out-of-band role, or the unbinder falls back to its conservative deferral) additionally grants cluster-scoped `nodes list` and `storageclasses get`. Both are read-only and consumed by the unbinder's new pvc-rebinding-gate exemption, which resolves a PV's pinned nodes by their `kubernetes.io/hostname` label and checks the unbound claim's StorageClass binding mode before acting. A new `statefulset.sideCars.pvcUnbinder.disableStuckClaimExemption` value renders the sidecar's `--disable-pvc-rebinding-gate-exemption` escape hatch, turning just that exemption off while keeping the PVCUnbinder running.
### Fixed
* Fixed an issue with post-upgrade processing of cluster configuration that resulted in configuration errors due to removed properties across Redpanda versions.
* Make configuration job pods have labels that don't overlap with StatefulSet pods so that they don't match selectors we use elsewhere.
* Fixed issue with ballast file tuning where the tuning container didn't mount the proper directory needed for propagating the ballast file to the main container.
* Fixed an issue where the bootstrap user password was not loaded from an externally-managed secret referenced via `auth.sasl.bootstrapUser.secretKeyRef`, causing SCRAM authentication to fail from the operator and other chart-owned clients.
* Fixed `ServiceMonitor` rendering to emit `scheme: http` / `scheme: https` (lowercase) instead of the uppercase Go constant values that older `prometheus-operator` CRDs rejected with `spec.endpoints[0].scheme: Unsupported value`. Restores the case that chart 25.3.x and earlier produced. Fixes #1511.
* Made StatefulSet lifecycle-hook timeouts visible in pod logs. The wrapper
previously ended every hook with `; true`, which swallowed timeout exit codes
(124 SIGTERM-on-timeout, 137 SIGKILL-on-timeout) and made the failure
indistinguishable from a clean run. When a hook is killed by `timeout`, the
wrapper now emits a clearly-marked line containing "TIMEOUT after Ns" with
the hook name (`pre-stop` or `post-start`) and exit code, so an operator
scanning pod logs after an ungraceful broker shutdown can immediately see
that the maintenance-mode drain (preStop) or the maintenance-mode clear
(postStart) didn't complete in its budget. The trailing `true` is retained
so non-zero exits don't poison container lifecycle on transient hook
issues — the TIMEOUT marker is the diagnostic signal.

* Boolean cluster properties set to `false` via `config.cluster` are no longer
silently overwritten by tiered storage defaults. Previously, setting a
property such as `cloud_storage_enable_remote_read: false` under
`config.cluster` had no effect because the merge that folds in tiered storage
defaults treated a boolean `false` as an empty value and let the default
(`true`) win. The rendered `.bootstrap.yaml` now honors an explicit `false`.

* `helm upgrade` no longer fails under Helm 4's default server-side apply when
SASL is enabled. To keep the generated bootstrap-user password stable, the
chart looks up the existing `*-bootstrap-user` Secret on upgrade and
re-renders it — previously verbatim, including the server-set
`metadata.managedFields`, which the API server rejects with
`metadata.managedFields must be nil` when Helm 4 applies manifests
server-side. The rejected apply also polluted release history: manifests
stored by any successful client-side upgrade carried `managedFields`, so
later server-side rollbacks failed the same way. The lookup now strips
`managedFields`, `resourceVersion`, and `uid` before the Secret is
re-rendered.

* The `postStart` lifecycle hook now clears maintenance mode left behind by a
previous incarnation of the pod that re-registered under a different node id
(e.g. after losing its data directory when running without persistent
storage). Previously the old node id was left in maintenance mode forever,
which blocked every other broker from entering maintenance mode and excluded
the ghost broker from the partition autobalancer's auto-decommission
(`partition_autobalancing_node_autodecommission_timeout_sec`). The hook only
clears ids the cluster reports dead (`is_alive=false`) and draining,
retrying briefly while the cluster's health monitor catches up with a fast
pod restart; a normal restart that keeps its node id is unaffected.
