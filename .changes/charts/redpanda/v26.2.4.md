## [v26.2.4](https://github.com/redpanda-data/redpanda-operator/releases/tag/charts%2Fredpanda%2Fv26.2.4) - 2026-09-24
### Added
* New `commonAnnotations` value adds the given annotations to every object the
  chart renders, including the StatefulSet itself. The StatefulSet's Pod
  template and volume claim templates are deliberately left unannotated: the
  claim templates are immutable on a live cluster, and annotating the Pod
  template would restart every broker. Annotations set on an individual
  resource take precedence. Useful for policy-engine required annotations or
  ArgoCD sync waves, for example `argocd.argoproj.io/sync-wave: "1"`.
### Changed
* Bump operator sidecar image tag to v26.2.4 release
* The default Redpanda version installed by the chart is now
  [v26.2.3](https://github.com/redpanda-data/redpanda/releases/tag/v26.2.3).
### Removed
* The chart no longer checks `image.tag` for compatibility. Deploying a
  Redpanda version older than the chart supports now fails at runtime rather
  than being caught up front by a render-time error, and the `force` value no
  longer has any effect.
### Fixed
* `resources.memory.container` no longer publishes a description belonging to
  another value

  The Helm reference showed "Enables memory locking. For production, set to
  `true`." for `resources.memory.container`. That text was written for the
  commented-out `resources.memory.enable_memory_locking` above it. The memory
  sizing guidance that also appeared there is unchanged.
* `helm install` prints the post-install notes again
