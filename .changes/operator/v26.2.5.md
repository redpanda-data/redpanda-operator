## [v26.2.5](https://github.com/redpanda-data/redpanda-operator/releases/tag/operator%2Fv26.2.5) - 2026-10-22
### Changed
* StretchCluster lifecycle hooks now log an explicit TIMEOUT line when `postStart.sh` or `preStop.sh` is killed at its timeout, matching the Helm chart. Previously the hook was killed silently and the broker received SIGTERM with no indication that the drain had not finished.
* The configurator and fs-validator script volumes on the `Redpanda` and `StretchCluster` Pods are now named `configurator` and `fs-validator` rather than `<fullname>-configurator` and `<fullname>-fs-validator`. Volume names are pod-local, so only the volume and volumeMount entries change; the Secrets they project are still named after the release and are untouched. This also fixes the configurator volume name exceeding Kubernetes' 63 character limit for releases whose fullname is 51 characters or longer.

  Upgrading an existing release changes the pod template and therefore rolls the brokers.

  If you override either of these volumes or volumeMounts through `podTemplate`, note that those lists are merged by name: an override keyed on the old `<fullname>-` prefixed name will silently stop matching and must be re-keyed to the new name.
* StretchCluster brokers now render their init containers through the same code as the Redpanda Helm chart, which changes two things in the generated StatefulSets. The `configurator` init container of StretchClusters now carry `securityContext.runAsNonRoot: true` and `securityContext.allowPrivilegeEscalation: false`, matching the chart and `Redpanda` Pods.

  This change will result in StretchCluster brokers restarting.
* `values.schema.json` now emits each type once under `$defs` and references it, rather than inlining every use site. The schema is unchanged in what it accepts, with one exception noted below, and is 3-5x smaller -- which every `helm template`, `helm install`, and `helm upgrade` pays to compile.

  Arrays nested inside a list or map of objects (for example `podTemplate.spec.containers[].args`) now accept `null` as well as a list, matching how arrays elsewhere in the schema already behaved.
* Bumped the default Redpanda Connect image for `Pipeline` resources to 4.115.0.
* The default Redpanda image tag (`--redpanda-tag`) is now
  [v26.2.6](https://github.com/redpanda-data/redpanda/releases/tag/v26.2.6),
  whose image no longer trusts the compromised eMudhra certificate authorities
  (CVE-2026-111943).
### Fixed
* The operator no longer sorts string-array cluster configuration values before applying them. Order-sensitive properties such as `kafka_mtls_principal_mapping_rules` and `sasl_kerberos_principal_mapping` (first match wins) and `iceberg_default_catalog_namespace` now keep the order given in the Redpanda resource. Previously, a `DEFAULT` rule could sort ahead of custom rules and map every principal to its full DN.
* SASL users from the users secret were sometimes never created. The sidecar started by `--watch-users` ran its first sync pass once and only retried a pass that failed to read a users file, so when the admin API of the broker was not yet listening (`connection refused`) or returned an error, the failure was logged and dropped and nothing re-ran the pass until the secret changed or the pod restarted. Broker CR clusters hit this on every bootstrap, because their sidecar starts in the same second as the `redpanda` container; StatefulSet clusters only when the sidecar raced the broker. A pass in which the admin API cannot serve a request now marks itself incomplete and is retried with backoff (250ms doubling up to 1min), like a pass with an unreadable users file; a user the API rejects (for example with an unsupported mechanism) is still logged and skipped.
* A `Console` that references a Redpanda cluster through `clusterRef` now connects to the cluster's NodePool brokers. Previously Console counted only the brokers of the cluster's own StatefulSet, so once a NodePool migration drained it to `statefulset.replicas: 0`, Console rendered no Kafka brokers or Schema Registry URLs and crash-looped with `you must specify at least one broker to connect to`. With `--enable-v2-nodepools`, Console now includes every NodePool bound to the cluster and re-renders when a NodePool is added, removed, or resized.
* A `Pipeline` that references a Redpanda cluster through `clusterRef` now connects to the cluster's NodePool brokers. Previously, once a NodePool migration drained the cluster's own StatefulSet to `statefulset.replicas: 0`, the Pipeline got no seed brokers. With `--enable-v2-nodepools`, Pipelines now include every NodePool bound to the cluster and pick up a NodePool being added, removed, or resized.
* Breaking change: NodePool brokers now inherit any unset `image` field from the
  Redpanda resource instead of the operator's default Redpanda image, which
  produced a mixed-version cluster when the Redpanda resource pinned
  `image.tag`. On upgrade, NodePools that leave `image` unset roll to the
  Redpanda resource's image. If that is older than the version they currently
  run, the roll is a downgrade that Redpanda may refuse to start on. Before
  upgrading, set `image.tag` on the Redpanda resource (or on the NodePool) to
  the version the NodePool runs today.
* Brokers managed by the Redpanda and StretchCluster resources could be left in maintenance mode after a rolling restart when they took longer than the `postStart` hook timeout (half the termination grace period) to start their admin API. The hook now clears maintenance mode in the background without that limit. See the `charts/redpanda` entry for details.
* The operator is now built with Go 1.26.10. Its `crypto/x509` package rejects
  certificates chaining to the eMudhra intermediate certificate authorities
  whose private keys were compromised (CVE-2026-111943), and its `net/http`
  package picks up fixes for several HTTP/2 denial-of-service vulnerabilities.
* Bumped `golang.org/x/net` to v0.60.0, `golang.org/x/crypto` to v0.57.0, and
  OpenTelemetry to v1.46.0 (logs v0.22.0) to address reported vulnerabilities,
  including a busy-spin in the OpenTelemetry log batch processor
  (CVE-2026-81872).
